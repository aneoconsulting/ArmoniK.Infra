Authentication in ArmoniK is enabled{{ if $cpRbac.createBuiltinRoles }}, default roles "Submitter" and "Monitoring" were created{{ end }}.
To query the cluster:

  1. Give each user an x509 certificate.
  2. Note each certificate's common name and fingerprint.
  3. Write a values file of this shape (replace the <...> placeholders):

### YAML start ###
init:
  enabled: true
rbac:
  authentication:
    required: true
{{- if not $cpRbac.createBuiltinRoles }}
  roles:
    <Role1>: [<Permission1>, <PermissionN>]
    <Role2>: [<Permission1>, <PermissionN>]
{{- end }}
  users:
    <username1>: [<RoleName1>, <RoleNameN>]
    <usernameN>: [<RoleName1>, <RoleNameN>]
  userCertificates:
    <username1>:
      commonName: <user1commonName>
      fingerprint: <user1fingerprint>
    <usernameN>:
      commonName: <userNcommonName>
      fingerprint: <userNfingerprint>
### YAML end ###
  4. Use the same keys in users and userCertificates.
  5. Pass it as a values file to a standalone control-plane (recipe below).
{{- end }}

The conf Secrets belong to this release ({{ .Release.Name }}), in namespace {{ $confNamespace }}.
A plane installed as its own release reads them with --set conf.source={{ .Release.Name }}, in the

Standalone planes assume the operators listed above are already in the cluster
(global.armonik.operators.<op>.available defaults to true). Pass
--set global.armonik.operators.<op>.available=false for each one NOT installed.

To add a standalone compute-plane with new partitions:

     helm install <release-name> ./charts/armonik-compute-plane \
       -n {{ $confNamespace }} \
       --set conf.source={{ .Release.Name }} \
      {{- if not $ownComputePlane }}
       --set serviceAccount.create=true \
      {{- end }}
      {{- if ne $mountPath "/mounts" }}
       --set conf.mountPath={{ $mountPath }} \
      {{- end }}
       -f <your-partitions>.yaml

To add a standalone control-plane (with optional external partitions):

     helm install <release-name> ./charts/armonik-control-plane \
       -n {{ $confNamespace }} \
       --set conf.source={{ .Release.Name }} \
      {{- if ne $mountPath "/mounts" }}
       --set conf.mountPath={{ $mountPath }} \
      {{- end }}
      {{- if $cpAuth.required }}
       -f <your-authentication-data>.yaml \
      {{- end }}
       [-f <your-control-plane>.yaml]

{{- /* CR types that are Helm hooks, i.e. whose operator this release installs (charts/uninstall.md). */}}
{{- $ops := include "armonik.operators" $ | fromYaml }}
{{- $drain := list }}
{{- if $ops.keda.deploy }}{{ $drain = append $drain "scaledobjects.keda.sh" }}{{ end }}
{{- if $ops.externalSecrets.deploy }}{{ $drain = concat $drain (list "externalsecrets.external-secrets.io" "secretstores.external-secrets.io") }}{{ end }}
{{- if $ops.certManager.deploy }}{{ $drain = concat $drain (list "certificates.cert-manager.io" "issuers.cert-manager.io") }}{{ end }}
{{- if $drain }}
This release installs its own operators, so the custom resources below are Helm hooks, which
helm uninstall does NOT delete. Delete them FIRST, while the operators still run, or their CRDs hang
in Terminating on orphaned resources no controller can finalize:

     for t in {{ join " " $drain }}; do
       kubectl delete "$t" -n {{ .Release.Namespace }} \
         -l app.kubernetes.io/instance={{ .Release.Name }} --ignore-not-found
     done

     helm uninstall {{ .Release.Name }} -n {{ .Release.Namespace }}

Deleting the ExternalSecrets also removes the conf Secrets they own, and deleting the Certificates the
TLS Secrets they own.
{{- else }}
Every operator comes from another release, so no custom resource is a Helm hook and a plain uninstall
is complete:

     helm uninstall {{ .Release.Name }} -n {{ .Release.Namespace }}

Uninstall the operators release only AFTER this one: its CRDs are cluster-scoped, and removing them
cascade-deletes the custom resources of every ArmoniK release in the cluster.
{{- end }}
