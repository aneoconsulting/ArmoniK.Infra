These operators and their CRDs are cluster-scoped and install-once. Every ArmoniK application release
consumes them by setting global.armonik.operators.<op>.available=true with deploy=false (the default
for the plane charts), which is also what keeps their custom resources out of Helm hooks and makes
those releases cleanly uninstallable.

**********************************************************
UNINSTALLING (full procedure and recovery steps: charts/uninstall.md)

Uninstall this release LAST, after every ArmoniK application release in the cluster. Its CRDs are
cluster-scoped: removing them cascade-deletes every matching custom resource in every namespace, and
any resource holding a controller finalizer (ScaledObject, ExternalSecret) then wedges in Terminating
because the controller that clears it goes down in this same uninstall.

     # 1. check nothing still uses the operators, in ANY namespace
{{- if $ops.keda.deploy }}
     kubectl get scaledobjects.keda.sh -A
{{- end }}
{{- if $ops.externalSecrets.deploy }}
     kubectl get externalsecrets.external-secrets.io,secretstores.external-secrets.io -A
{{- end }}
{{- if $ops.certManager.deploy }}
     kubectl get certificates.cert-manager.io,issuers.cert-manager.io -A
{{- end }}
{{- if $ops.mongodbOperator.deploy }}
     kubectl get perconaservermongodbs.psmdb.percona.com -A
{{- end }}

     # 2. then remove this release
     helm uninstall {{ .Release.Name }} -n {{ .Release.Namespace }}
