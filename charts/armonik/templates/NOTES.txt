{{- $mountPath := include "armonik.conf.mountPath" $ }}
The configuration Secrets are owned by this release ({{ .Release.Name }}) and live in namespace
{{ .Release.Namespace }}. To install a plane as a separate release, point it at those Secrets with
--set conf.source={{ .Release.Name }} and install it in the SAME namespace. (A plane in another
namespace needs the Secrets mirrored there, e.g. via an ESO remoteNamespace ExternalSecret.)
{{- if ne $mountPath "/mounts" }}
This release overrides the conf mount path; a standalone plane must also set
--set conf.mountPath={{ $mountPath }} so it mounts the config where the Secrets expect it.
{{- end }}

Standalone planes assume the cluster already provides the operators (KEDA, External Secrets,
cert-manager, psmdb-operator, prometheus-operator): global.armonik.operators.<op>.available defaults
to true. Pass --set global.armonik.operators.<op>.available=false for any operator NOT installed.

To add a standalone compute-plane with new partitions:

     helm install <release-name> ./charts/armonik-compute-plane \
       -n {{ .Release.Namespace }} \
       --set conf.source={{ .Release.Name }} \
      {{- if ne $mountPath "/mounts" }}
       --set conf.mountPath={{ $mountPath }} \
      {{- end }}
       -f <your-partitions>.yaml

To add a standalone control-plane (with optional external partitions):

     helm install <release-name> ./charts/armonik-control-plane \
       -n {{ .Release.Namespace }} \
       --set conf.source={{ .Release.Name }} \
      {{- if ne $mountPath "/mounts" }}
       --set conf.mountPath={{ $mountPath }} \
      {{- end }}
      {{- if $cpAuth.required }}
       -f <your-authentication-data>.yaml \
      {{- end }}

UNINSTALLING (full procedure and recovery steps: charts/uninstall.md)

{{- /* Operators installed BY this release render their CRs as post-install hooks (the CRD does not
       exist yet when the main manifest is applied). Helm does not track hook resources, so those CRs
       outlive `helm uninstall` and wedge the CRD deletion. Types listed only when hooked. */}}
{{- $ops := include "armonik.operators" $ | fromYaml }}
{{- $drain := list }}
{{- if $ops.keda.deploy }}{{ $drain = append $drain "scaledobjects.keda.sh" }}{{ end }}
{{- if $ops.externalSecrets.deploy }}{{ $drain = concat $drain (list "externalsecrets.external-secrets.io" "secretstores.external-secrets.io") }}{{ end }}
{{- if $ops.certManager.deploy }}{{ $drain = concat $drain (list "certificates.cert-manager.io" "issuers.cert-manager.io") }}{{ end }}
{{- if $drain }}
This release installs its own operators, so the custom resources below are applied as Helm hooks, and
Helm does NOT delete hook resources on uninstall. Delete them FIRST, while the operators are still
running, otherwise their CRDs hang in Terminating with orphaned resources no controller can finalize:

     for t in {{ join " " $drain }}; do
       kubectl delete "$t" -n {{ .Release.Namespace }} \
         -l app.kubernetes.io/instance={{ .Release.Name }} --ignore-not-found
     done

     helm uninstall {{ .Release.Name }} -n {{ .Release.Namespace }}

Deleting the ExternalSecrets also removes the conf Secrets they own; deleting the Certificates removes
the TLS Secrets they own.
{{- else }}
Every operator used here comes from another release, so no custom resource is applied as a Helm hook
and a plain uninstall is complete:

     helm uninstall {{ .Release.Name }} -n {{ .Release.Namespace }}

Uninstall the operators release only AFTER this one: its CRDs are cluster-scoped, and removing them
cascade-deletes the custom resources of every ArmoniK release in the cluster.
{{- end }}
