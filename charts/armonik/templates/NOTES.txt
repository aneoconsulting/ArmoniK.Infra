Authentication in ArmoniK is enabled{{ if (index .Values "control-plane").rbac.createBuiltinRoles }}, default roles "Submitter" and "Monitoring" were created{{ end }}.
Since authentication inside ArmoniK in enabled, you must apply the following steps to be able to query your ArmoniK cluster :

  1. Make sure your users hold a x509 certificate
  2. For each user, check their certificate common name and fingerprint (keep them for the next step)
  3. Create a YAML file with the following structure (replace brackets-wrapped values with your own): 
  
### YAML start ###
init:
  enabled: true
  rbac:
{{- if not (index .Values "control-plane").rbac.createBuiltinRoles }}
    roles:
      <Role1>: [<Permission1>, <PermissionN>]
      <Role2>: [<Permission1>, <PermissionN>]
{{- end }}
    users:
      <username1>: [<RoleName1>, <RolesNameN>]
      <usernameN>: [<RoleName1>, <RolesNameN>]
    userCertificates:
      <username1>:
        commonName: <user1commonName>
        fingerprint: <user1fingerprint>
      <usernameN>:
        commonName: <userNcommonName>
        fingerprint <userNfingerprint>
### YAML end ###
  4. Make sure userCertificates and users maps share the same keys.
  5. Use this YAML file as a values file for a standalone control-plane (further details below)
{{- end }}

{{- $mountPath := include "armonik.conf.mountPath" $ }}
The configuration Secrets are owned by this release ({{ .Release.Name }}) and live in namespace
{{ .Release.Namespace }}. To install a plane as a separate release, point it at those Secrets with
--set conf.source={{ .Release.Name }} and install it in the SAME namespace. (A plane in another
namespace needs the Secrets mirrored there, e.g. via an ESO remoteNamespace ExternalSecret.)
{{- if ne $mountPath "/mounts" }}
This release overrides the conf mount path; a standalone plane must also set
--set conf.mountPath={{ $mountPath }} so it mounts the config where the Secrets expect it.
{{- end }}

Standalone planes assume the cluster already provides the operators (KEDA, External Secrets,
cert-manager, psmdb-operator, prometheus-operator): global.armonik.operators.<op>.available defaults
to true. Pass --set global.armonik.operators.<op>.available=false for any operator NOT installed.

To add a standalone compute-plane with new partitions:

     helm install <release-name> ./charts/armonik-compute-plane \
       -n {{ .Release.Namespace }} \
       --set conf.source={{ .Release.Name }} \
      {{- if ne $mountPath "/mounts" }}
       --set conf.mountPath={{ $mountPath }} \
      {{- end }}
       -f <your-partitions>.yaml

To add a standalone control-plane (with optional external partitions):

     helm install <release-name> ./charts/armonik-control-plane \
       -n {{ .Release.Namespace }} \
       --set conf.source={{ .Release.Name }} \
      {{- if ne $mountPath "/mounts" }}
       --set conf.mountPath={{ $mountPath }} \
      {{- end }}
      {{- if (index .Values "control-plane").rbac.authentication.required }}
       -f <your-authentication-data>.yaml \
      {{- end }}
       [-f <your-control-plane>.yaml]
